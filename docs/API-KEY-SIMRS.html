API Key Bridge SIMRS ↔ Orthanc PACS

Panduan untuk tim SIMRS: cara memperoleh API key, cara mengirimkannya, endpoint mana yang memerlukan key, contoh kode siap pakai (PHP / CodeIgniter / Python), status order, callback study baru, audit panggilan, serta penanganan error.

Dokumen ini tidak memuat nilai API key. Key bersifat rahasia (setara password — memberi akses ke data pasien). Minta nilainya ke admin PACS lewat jalur aman, lalu simpan di environment / secret manager SIMRS, bukan di source code.

Ringkasan tiga langkah

1. Dapatkan key
Admin PACS membuat key di dashboard → ⚙ Pengaturan → panel API Bridge → Generate, lalu menyerahkannya lewat kanal aman.		 2. Simpan & kirim
Simpan sebagai environment variable (mis. PACS_BRIDGE_KEY) dan kirim pada setiap request sebagai header X-API-Key.		 3. Panggil endpoint data
Worklist, study, gambar, dan ZIP bisa diakses dengan key. Endpoint administratif (Pengaturan, user) tetap butuh sesi login manager.

1. Konsep: dua cara SIMRS terhubung

CaraAlurAutentikasi
A. Bridge SDK langsung ke Orthanc
(library Bridge, WorklistService, StudyService)		 SIMRS → DICOM/REST Orthanc 10.4.0.10 Tidak memakai API key; pengamanannya di level jaringan (LAN/VPN) karena REST Orthanc saat ini tanpa autentikasi.
B. Bridge API (HTTP)
(public/index.php)		 SIMRS → http://10.4.0.10/ dengan header X-API-Key → Orthanc API key. Inilah yang dibahas di dokumen ini.

Kapan memilih cara B? Bila SIMRS hanya membutuhkan order worklist, pencarian study, dan pengambilan gambar/ZIP — tanpa perlu menjadi SCU DICOM. Cara B memberi aturan terpusat: validasi, nama pasien tanpa koma, tanggal order, render JPG/PNG, watermark, dan filter tanggal.

1.1 Dari mana API key berasal

  1. Dashboard bridge → login sebagai manager → ⚙ Pengaturan → panel API Bridge → field API Key → tombol Generate (48 karakter heksadesimal) → Simpan Pengaturan.
  2. Disimpan di server pada data/settings.json (tidak ikut paket deploy, tidak di-commit).
  3. Alternatif: environment variable PACS_BRIDGE_KEY pada container — prioritas tertinggi, tidak menulis file.

Nilai utuh key hanya bisa dibaca lewat sesi login manager: dashboard (tombol Sembunyikan / Salin) atau GET /settings/api-key. Endpoint ini menolak pemanggilan dengan API key (403) supaya key tidak bisa membocorkan dirinya sendiri.

2. Cara mengirim API key

Key dikirim hanya lewat header HTTP pada setiap request. Nama header tidak peka huruf (x-api-key boleh), tetapi nilainya dibandingkan persis — jangan menambah spasi, baris baru, atau tanda kutip.

CaraContohDiterima?
Header HTTPX-API-Key: 0123abcd…beefYa
Query string/health?api_key=0123abcd…Tidak → 401
Body JSON{"api_key": "0123abcd…"}Tidak → 401
Cookieapi_key=…Tidak → 401
Basic/Bearer authAuthorization: Bearer …Tidak → 401

Preflight CORS (OPTIONS) tidak memerlukan key dan selalu dijawab 204, sehingga pemanggilan fetch/XHR dari browser tidak terblokir.

2.1 curl

BASE="http://10.4.0.10"
KEY="<API_KEY>"

curl -H "X-API-Key: $KEY" "$BASE/health"
curl -H "X-API-Key: $KEY" "$BASE/worklists"
curl -H "X-API-Key: $KEY" "$BASE/studies/A261105038/jpg?quality=90" -o hasil.jpg

2.2 PowerShell

$base = 'http://10.4.0.10'
$key  = $env:PACS_BRIDGE_KEY
$h    = @{ 'X-API-Key' = $key }

Invoke-RestMethod "$base/health" -Headers $h
Invoke-WebRequest  "$base/studies/A261105038/jpg?watermark=1" -Headers $h -OutFile hasil.jpg

2.3 PHP (cURL)

<?php
$ch = curl_init('http://10.4.0.10/health');
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => ['X-API-Key: ' . getenv('PACS_BRIDGE_KEY')],
    CURLOPT_TIMEOUT        => 30,
]);
$json = json_decode((string) curl_exec($ch), true);
$code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
curl_close($ch);

5. Contoh integrasi SIMRS

5.1 PHP native — pakai BridgeApiClient (tanpa dependency)

<?php
require_once '/path/ke/PACSPROJEC/src/autoload.php';

use Simrs\Pacs\BridgeApiClient;

$api = new BridgeApiClient('http://10.4.0.10', getenv('PACS_BRIDGE_KEY'));

$api->health();                                        // status Orthanc & worklist

$api->createWorklist([
    'patient_name'     => 'TARYA BIN WARDI',
    'title'            => 'Tn.',
    'patient_id'       => 'A048919',
    'accession_number' => 'A261105038',
    'procedure'        => 'THORAX PA',
    'modality'         => 'DX',
    'station_aet'      => 'LEAD_CLIENT',
]);

$studies = $api->findStudiesByAccession('A261105038');
$jpg     = $api->jpegByAccession('A261105038', 90);    // ['content','mime','filename'] | null
$zip     = $api->zipByAccession('A261105038');         // string biner ZIP | null

Error dilempar sebagai Simrs\Pacs\BridgeApiException (berisi statusCode).

5.5 Menyimpan key di SIMRS

  • Simpan sebagai environment variable (PACS_BRIDGE_KEY) atau secret manager .env CI — jangan di application/config/*.php yang ikut versioning.
  • Satu key untuk satu instalasi SIMRS; jangan dibagikan ke aplikasi lain bila tidak perlu.
  • Jangan menulis key ke log, pesan error, atau tampilan halaman.

5.7 Callback study baru (tanpa polling)

Isi Callback URL dan Callback key di dashboard (⚙ Pengaturan). Worker tools/notify-studies.php (cron tiap menit) memantau /changes Orthanc dan mengirim POST ke URL SIMRS saat ada study stabil baru.

POST /api/pacs/callback
Content-Type: application/json
X-Bridge-Event: study.received
X-Bridge-Key: <CALLBACK_KEY>
X-Bridge-Signature: sha256=9f2c...e1

{
  "event": "study.received",
  "accession_number": "A261105038",
  "patient_id": "A048919",
  "study_id": "9060f064-48cfbfa5-63c41030-bf2967f1-e70f790e",
  "study_instance_uid": "1.2.840.114257.1.1.11232.191827.7270194.100",
  "study_date": "20261119",
  "modalities": ["DX"],
  "images": 1,
  "status": "completed"
}
// verifikasi tanda tangan di SIMRS
$raw = file_get_contents('php://input');
$expect = 'sha256=' . hash_hmac('sha256', $raw, getenv('PACS_CALLBACK_KEY'));
if (!hash_equals($expect, $_SERVER['HTTP_X_BRIDGE_SIGNATURE'] ?? '')) {
    http_response_code(401);
    exit;
}
$event = json_decode($raw, true);
http_response_code(200);   // wajib 2xx

Pengiriman bersifat at-least-once (retry 3×, sisa dicoba pada jadwal berikutnya) — SIMRS wajib mengabaikan study_id yang sudah diproses.

5.8 Audit panggilan

Setiap request dicatat otomatis ke data/audit.log (JSON Lines: waktu, IP, kredensial, metode, path, status, durasi, accession). Aksi penting tercatat sebagai event (worklist.create, worklist.delete, settings.update, auth.login, …). Riwayat dibaca lewat GET /audit (sesi manager):

curl -b cookies.txt "http://10.4.0.10/audit?limit=20"
curl -b cookies.txt "http://10.4.0.10/audit?accession=A261105038"
curl -b cookies.txt "http://10.4.0.10/audit?event=worklist.delete"

API key & operator → 403. File dirotasi otomatis pada 5 MB (audit.log.1) dan tidak pernah memuat nilai API key.

5.9 Draf expertise AI (opsional)

Bila manager mengaktifkan Auto Expertise (Ollama) di Pengaturan, bridge bisa membuat draf bacaan dari satu gambar study memakai model vision di jaringan lokal (bukan layanan internet):

curl -H "X-API-Key: $KEY" "$BASE/ollama/status"                       # reachable, vision_models, model_ready
curl -X POST -H "X-API-Key: $KEY" "$BASE/studies/A261105038/expertise"
curl -H "X-API-Key: $KEY" "$BASE/studies/A261105038/expertise"        # draf tersimpan

Respons memuat draft (kesan, temuan utama/lain, rekomendasi, keyakinan) dan disclaimer. Hasil wajib diverifikasi dokter — bukan diagnosis. Citra dikirim ke model tanpa watermark dan hanya ke server Ollama di LAN. 503 bila fitur belum diaktifkan; panggilan pertama lebih lambat karena model dimuat.

6. Alur integrasi yang disarankan

  1. Health check saat SIMRS start / berkala: GET /health dengan key. Periksa worklist.reachable — Orthanc bisa hidup sementara service MWL mati.
  2. Nomor accession: GET /accession (format alat Orthanc), atau kirim accession milik SIMRS.
  3. Kirim order: POST /worklists saat pasien didaftarkan. accession_number yang dikembalikan adalah kunci untuk mencari hasil.
  4. Ambil hasil: GET /studies?accession=… secara berkala (polling) hingga study muncul, lalu GET /studies/{acc}/jpg?watermark=1 atau /zip-jpg.
  5. Simpan gambar di SIMRS seperlunya (bridge bersifat stateless — tidak menyimpan gambar).

Catatan operasional penting

  • ScheduledProcedureStepStartDate harus hari ini (Ymd), kalau tidak order tidak terlihat alat.
  • modality tidak dibatasi DX: nilai config/PACS_MODALITY hanya default. Kirim "modality":"CT" / "US" / "ECG" + station_aet alat untuk order modalitas lain (alat tetap harus terdaftar di Orthanc).
  • AE Title alat case-sensitive; kirim huruf asli (VersanaB-000000, bukan VERSANAB-000000).
  • PatientName diformat tanpa koma; gunakan helper/PatientName::safe() bila mengirim lewat SDK.
  • Sebagian alat (mis. USG) mengirim study tanpa AccessionNumber. Untuk study seperti itu, pakai ID Orthanc dari respons /studies/recent sebagai kunci gambar/ZIP.
  • JPG/PNG hasil render bukan citra diagnostik (lossy, 8-bit).
  • Timeout ZIP ≥ 60 detik; batasi unduhan paralel 3–4 gambar agar Orthanc tidak timeout.

7.1 Bentuk respons error

// 401
{"error": "Unauthorized", "message": "Silakan login di dashboard"}

// 403 (contoh)
{"error": "API key hanya bisa dilihat lewat sesi login"}

// 502
{"error": "Orthanc error", "message": "…", "orthanc_status": 0, "orthanc_body": ""}

Saran: bedakan penanganan 4xx (jangan retry kecuali 401 setelah memperbaiki key) dan 5xx/502 (retry dengan backoff 2–5 detik, maksimum 3 kali).

8. Keamanan & rotasi key

  • Perlakukan seperti password. Key memberi akses penuh data pasien (nama, No. RM, gambar).
  • Wajib HTTPS bila melewati jaringan non-LAN (mis. lewat internet/VPN publik).
  • Jangan commit key ke repo; jangan tampilkan di UI SIMRS atau log.
  • Rotasi: manager membuat key baru di dashboard → perbarui environment SIMRS → restart service pemanggil. Key lama otomatis tidak berlaku karena hanya satu key aktif.
  • Cabut akses program: kosongkan field API Key lalu simpan — mode kembali ke sesi login saja.
  • Batasi jaringan: API sebaiknya hanya dapat dijangkau dari LAN RS / VPN.
  • Nilai key di GET /settings selalu ter-mask (8 karakter awal … 4 karakter akhir).
